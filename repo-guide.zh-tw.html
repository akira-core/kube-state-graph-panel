1. 這個 repo 是什麼

kube-state-graph-panel 是一個 Grafana 12.x 的 panel plugin。它負責把 Kubernetes 資源拓撲，例如 Pod、Service、Node、PVC 與它們之間的關係，渲染成互動式 graph。

這個 repo 只做前端 panel，不包含 Go backend。產生 graph JSON 的服務是上游 marz32one/kube-state-graph Docker image。kube-state-graph backend 是從 PromQL（一個 [start,end] 時間窗）衍生出整張拓撲圖，它不讀 Kubernetes API；資料實際來自一個 Prometheus 相容的 metrics store。本 panel 透過 Grafana 的 Infinity datasource 呼叫 backend 的 GET /v1/graph，再把回來的 JSON 正規化成 cytoscape elements。

這個 repo 負責

  • Grafana panel plugin 註冊與 options editor。
  • 把 Grafana datasource response 轉成 graph elements（含 controller 合成、switch fabric、alerts 聚合）。
  • 用 cytoscape.js 顯示、layout、resize、tooltip、legend、filter、expand-collapse。
  • Node Detail 面板（Alerts / Application / Containers）與 lazy Change Report lookup。
  • Pod 名稱匯出至 dashboard 變數（供下游 logs panel 等 consumer）。
  • 提供 Compose profile demo（Showcase 無 backend + Demo 全 stack）與測試工具鏈。

這個 repo 不負責

  • 不直接連 Kubernetes API。
  • 不內嵌 kube-state-graph backend 原始碼。
  • 不自建 Grafana backend datasource plugin。
  • 不處理正式 plugin signing 與 catalog 發佈流程。
一句話版：這是一個「Grafana panel 前端」，輸入是 backend 產生的 cytoscape-style JSON，輸出是可互動的 Kubernetes topology graph。

2. 快速開始

環境需求

  • Node 22+
  • npm 11+，目前 package.json 指定 npm@11.13.0
  • Docker with Compose v2
不需要 Kubernetes cluster。demo 是完全自包含的：compose 會起一個 VictoriaMetrics 與一個 seeder，把合成的 topology metrics 灌進去餵給 backend。不需要 kubeconfig，也沒有 KUBECONFIG_PATH 這個變數。要改指向真實資料時，才在 kube-state-graph service 上設 KSG_PROM_URL 指到你自己的 VictoriaMetrics，並移除 ksg-seeder。

第一次安裝

npm install

啟動開發模式

建議開兩個 terminal：

Terminal A：build plugin 到 dist

npm run dev

這會執行 webpack watch。你改 src/** 後，bundle 會重新輸出到 dist/。

Terminal B：啟動 demo stack

# 僅 Grafana + Showcase（不需 backend）
docker compose up -d

# 完整 stack（VictoriaMetrics + seeder + backend）
docker compose --profile backend up -d
# 等同 npm run server（會先 build 再 up）

Compose 使用 profile 切換：backend profile 才會起 VictoriaMetrics、seeder 與 kube-state-graph。預設 up 只起 Grafana，足夠跑 KSG Showcase。

兩種 demo 模式

Dashboard URL 需要 backend profile？ 說明
KSG Showcase /d/ksg-switch-demo 否 Infinity INLINE target，內嵌合成拓撲 JSON；展示 switch fabric、StorageClass 分組、controller 聚合等 panel 能力，零 backend。
KSG Demo /d/ksg-demo 是 透過 provisioned Infinity datasource 打真實 kube-state-graph backend；含 template variables（cluster / namespace / name / edge_type）與 pod_list 變數匯出範例。

docker compose 起了哪些 service？

Service Profile 角色
grafana （永遠） 掛載 dist/ 載入本 panel，provision 兩份 dashboard（Showcase + Demo）與 Infinity datasource。
kube-state-graph（ksg-backend） backend kube-state-graph backend；KSG_PROM_URL 指向 VictoriaMetrics。
victoriametrics backend backend 的拓撲資料來源（PromQL）。
ksg-seeder backend 每隔 SEED_INTERVAL 秒重新 push 合成 fixture（含遞增的 service-graph counter、 argocd_tracking_id、container_info 等），讓 last_over_time(...) 與 rate(...) 維持新鮮，並餵足 node-detail 的 Application / Containers 區塊。

打開 Grafana

open http://localhost:3000

依你啟動的 profile 選 dashboard：KSG Showcase（/d/ksg-switch-demo）隨時可用； KSG Demo（/d/ksg-demo）需 --profile backend，否則 datasource 錯誤屬預期行為。

Hot reload 心法：npm run dev 只負責更新 dist/。Grafana container 通常不用重啟，但瀏覽器需要重新整理，常用 Cmd + R。

3. 先建立心智模型

如果你不熟 React，可以先把整個系統想成一條資料管線，而不是很多 component。

1. Backend 回傳 JSON
kube-state-graph 從 PromQL（一個 [start,end] 時間窗）衍生出 { elements: { nodes, edges } }，不讀 Kubernetes API。
2. Grafana datasource query
Infinity datasource 把 HTTP response 包進 Grafana 的 PanelData.series。
3. useGraphData 解資料
useGraphData 從 frames 中挑出 graph payload，交給 normalizeGraph。
4. normalizeGraph 當防腐層
把上游欄位 type、name、ipaddress 映射成 panel 內部欄位 kind、label、ipAddress。
6. View transforms（panel 端視圖）
applyPodParentMode 切換 pod 嵌在 K8s node 或 workload controller 底下； wrapSwitchFabric 為無 parent 的 switch 合成 network 容器。
7. GraphCanvas 管 cytoscape
React 只建立容器與呼叫 hooks；真正的 graph 狀態在 cytoscape instance 裡。
8. hooks 負責 imperative 更新
useCytoscape 建 instance 與 diff elements； useGraphLayout 跑 layout； useElementFilter 改 visibility； HoverTooltip 監聽 hover； tap / cxttap 驅動 NodeDetailPanel。
最重要的架構規則：React 不是 graph 狀態的 source of truth。cytoscape instance 才是。 React 負責 mount/unmount 與把 props 變化同步進 cytoscape。

逐步細節（cytoscape JSON 契約、deserialization、stylesheet 如何套到 node/edge）見 §5 渲染管線與 cytoscape 格式。

Feature-first 是什麼？

Feature-first 是一種目錄組織方式：用「功能領域」切資料夾，而不是用「檔案類型」切資料夾。 這個 repo 的 features/ 就是用 feature-first。當你要改 graph canvas、資料轉換、tooltip、 legend 或 filter 時，相關 component、hook、純函式與測試會盡量靠在同一個 feature 裡。

Type-first 的問題

很多 React 專案一開始會用 type-first，也就是依照檔案類型分資料夾：

src/
├── components/
├── hooks/
├── types/
├── utils/
├── constants/
└── tests/

這種方式小專案還可以，但功能變多後，要改「graph canvas」時可能要在 components/、hooks/、utils/、types/ 到處找。 你知道自己要改哪個功能，卻被迫先猜檔案類型。

Feature-first 在這個 repo 的樣子

features/graph-canvas/
├── components/
│   └── GraphCanvas/
├── hooks/
│   ├── useCytoscape.ts
│   ├── useGraphLayout.ts
│   └── useGraphResize.ts
├── styles/
│   └── getStylesheet.ts
├── sync/
│   └── diffElements.ts
└── index.ts

這代表「畫 graph」這個功能的主要程式碼都集中在 graph-canvas。 如果你要 debug cytoscape instance、layout、resize、stylesheet 或 element sync， 第一個要看的地方就是這個 feature。

這個 repo 哪些地方使用 feature-first？

Feature 負責什麼 常見修改情境

Feature-first 怎麼 work：barrel 當 public API

每個 feature 通常會有一個 index.ts，也叫 barrel。外部只從 barrel import 這個 feature 願意公開的 API，不直接鑽進內部路徑。這能讓 feature 內部重構時，外部不需要跟著改。 

// KsgPanel.tsx
import {
  EmptyState,
  GraphCanvas,
  LoadingOverlay,
} from '../../features/graph-canvas';

上面這種 import 表示 KsgPanel 只知道 graph-canvas 對外提供 GraphCanvas、EmptyState、LoadingOverlay。 它不需要知道這些檔案實際在 components/GraphCanvas/GraphCanvas.tsx 還是其他內部位置。

什麼該放 feature？什麼該放 shared？

放 feature

只服務單一功能的程式碼，放在該 feature 裡。

  • features/element-filter/computeVisibility.ts
  • features/hover-tooltip/hooks/useHoverElement.ts
  • features/graph-canvas/sync/diffElements.ts

放 shared

真的被多個 feature 共用，而且代表跨功能契約的東西，才放 shared。

  • shared/constants/iconSvgByKind.ts
  • shared/constants/colorByEdgeType.ts
  • shared/constants/categoryByKind.ts
  • shared/types/cytoscape.d.ts
判斷口訣：如果你會說「我要改 filter 功能」，那它多半在 feature。 如果你會說「graph style、legend、filter 都要共用同一份 node kind 圖示 map」，那它才適合進 shared。

5. 渲染管線與 cytoscape 格式

這一節把「從 backend JSON 到畫面上每一個 node / edge 長什麼樣」拆成可追蹤的步驟。 如果你要 debug「資料有進來但畫面不對」或「新增一種 kind 要改哪裡」，先對照這條管線。

5.1 端到端渲染管線

整條路徑可以分成 資料反序列化 與 cytoscape imperative 渲染 兩大半：

A. HTTP → Grafana PanelData
Infinity datasource 呼叫 GET /v1/graph，把 JSON 包進 PanelData.series[].fields[].values[0]（可能是字串或已解析物件）。
B. extractJsonFromFrames（挑 payload）
useGraphData 掃描所有 frame / field，JSON.parse 字串欄位，用 looksLikeGraphPayload 挑出含 elements 或 nodes 的物件。
C. normalizeGraph（反序列化 + 映射）
驗證形狀、把上游 data.type / data.name 等欄位映射成 panel 內部 kind / label，產出 cytoscape.ElementDefinition[]。
D. KsgPanel orchestrator + view transforms
處理 loading / error / empty；applyPodParentMode + wrapSwitchFabric 產生畫布用 elements；useGraphTheme 算出 stylesheet；傳給 GraphCanvas 與 legend / detail panel。
E. useCytoscape — 建立 instance
空 deps effect 建立 cytoscape({ container, elements, style, layout: preset })。 不在 constructor 跑 fcose/dagre，避免 mount 時 double layout。
F. diffElements — 增量同步
比較 cy.elements().jsons() 與 incoming elements，只 add / remove / update 差異，包在 cy.batch() 裡。
G. cy.style(stylesheet).update()
theme 或常數 map 變動時換 stylesheet，不重建 instance。
H. useGraphLayout — 佈局
cy.stop() 後 cy.layout({ name: 'fcose' | 'dagre' }).run()。這是 layout 的 唯一執行點。
I. useElementFilter — 可見性
依 visible kinds / edge types 對每個 element 設 visibility: visible | hidden（不刪元素、不重跑 layout）。
J. useGraphResize + 互動層
ResizeObserver → cy.resize() / cy.fit()；hover tooltip、tap 選取、expand-collapse 疊在最上層。
核心原則：React props 驅動的是「要同步進 cytoscape 的資料與設定」；畫布上的位置、選取、visibility 等 runtime 狀態由 cytoscape instance 持有，透過 hooks 以 imperative API 更新。

5.2 上游 cytoscape JSON 契約

上游 kube-state-graph 的 GET /v1/graph 輸出 cytoscape.js elements 形式 的 JSON。頂層長這樣： 

{
  "apiVersion": "…",
  "clusters": ["prod", "dr"],
  "elements": {
    "nodes": [ … ],
    "edges": [ … ]
  }
}

每個 node / edge 條目遵循 cytoscape 慣例，資料包在 data 物件裡（panel 也容忍扁平物件，見 §5.4）：

// Node（上游 wire 格式）
{
  "data": {
    "id": "prod/shop/checkout-0",
    "name": "checkout-0",
    "type": "pod",
    "parent": "prod/node/worker-1",
    "status": "normal",
    "ipaddress": ["10.0.1.5"],
    "labels": { "namespace": "shop" }
  }
}

// Edge（上游 wire 格式）
{
  "data": {
    "id": "e1",
    "type": "pod-calls-pod",
    "source": "prod/shop/gateway",
    "target": "dr/app/consumer",
    "labels": { }
  }
}

Compound（巢狀）結構由 backend 決定

backend 會 emit compound nodes：type: "cluster" 的合成群組包住各 cluster 內資源；pod 嵌在 K8s node 底下。 pod-runs-on-node 關係不畫成 edge，而是以 parent 巢狀表達（design D31）。panel 對 parent 欄位原樣 pass-through，只額外替 cluster 容器加上 accent 色（clusterColor）。

5.3 Deserialization：從 Grafana frame 到 ElementDefinition

「反序列化」在本 repo 指兩步：從 PanelData 抽出 JSON + normalize 成 typed elements。

步驟 1 — extractJsonFromFrames

檔案：features/graph-data/hooks/useGraphData.ts

PanelData.series[]
  └── DataFrame.fields[]
        └── field.values[0]

// 對每個 candidate：
// 1. 若 typeof raw === 'string' → JSON.parse(raw)
// 2. looksLikeGraphPayload(candidate) ?
//      isPlainObject(v) && (isPlainObject(v.elements) || Array.isArray(v.nodes))
// 3. 第一個符合的 graph payload 立即 return
// 4. 否則 fallback 到第一個可 parse 的值，讓 normalizeGraph 回報錯誤
Infinity datasource 的 table flatten 行為不固定，同一個 response 可能同時出現 apiVersion、clusters、elements 等多欄。 looksLikeGraphPayload 的目的就是跳過非 graph 欄位，只挑真正的 topology payload。

步驟 2 — normalizeGraph（防腐層）

檔案：features/graph-data/normalize.ts — 純函式，無 I/O，相同輸入必得相同輸出。

normalizeGraph(raw: unknown)
  → { elements: cytoscape.ElementDefinition[], errors: string[] }

normalize 容忍的頂層形狀：

  • 完整 envelope：{ elements: { nodes, edges }, … }
  • 已解包：{ nodes, edges }

每個 node / edge 條目容忍：

  • cytoscape 包裝：{ data: { id, type, … } }
  • 扁平：{ id, type, … }（unwrapData 優先取 entry.data）

6. Node Detail 面板

選取節點後，畫布底部會浮出 NodeDetailPanel（z-index 1000，高於 cytoscape 的透明 input canvas）。 這是 incident triage 的主要出口：從拓撲節點跳到告警時間軸、ArgoCD application、container image 詳情。

6.1 左鍵 vs 右鍵：兩種 view

手勢 cytoscape 事件 Panel view 顯示內容
左鍵 tap tap → onSelect alerts 僅 Alerts 表格（Count / Last occurred / severity / 可點時間 rewind ±5 分鐘）
右鍵 cxttap → onContextSelect detail 僅 Application + Containers 區塊（需 kind ∈ Workloads 且有對應資料）
點背景 / 關閉 tap background / close button — 清除選取與 detail 查詢意圖
右鍵必須抑制原生 context menu。GraphCanvas 在 container 上監聽 contextmenu 並 preventDefault()，否則瀏覽器選單會蓋過 panel 互動。

6.2 哪些節點會顯示 Application / Containers？

DETAIL_URL_KINDS 從 categoryByKind.ts 的 Workloads 類別派生：pod 與五種 workload controller（deployment、statefulset、daemonset、job、 cronjob）。還需節點實際帶有 application / containers 欄位——舊版 backend 缺欄位時區塊自動隱藏。

  • Application 區塊：一列 ArgoCD application name + Change Report 按鈕。
  • Containers 區塊：每列 container name、image、Change Report 按鈕；controller 節點的 containers 由 normalize 自子 pod 聚合去重。

6.3 Lazy Change Report lookup

useNodeDetailUrls 採點擊才查（lazy）模式：右鍵開面板時不自動打 REST，預設只顯示可點的 Change Report 按鈕；使用者點擊後才查 backend，成功以 window.open 開新分頁，失敗在按鈕左側顯示錯誤（可重試）。

Endpoint 解析（resolveDetailEndpoint）
1) panel option detailEndpoint 非空 → 直接用；2) 否則從 dashboard query 的 datasource ref 推導 Grafana proxy base （/api/datasources/proxy/uid/<uid>）；3) 皆無 → enabled: false，按鈕停用、永不發查詢。
查詢 input（右鍵當下凍結）
{ application, kind, name, time } — time 為右鍵當下 Unix 秒；pod 的 kind/name 取自 owner，controller 取自身。
Application 按鈕 → GET …/api/v1/config_changes
回傳 { "url": string }；成功開 ArgoCD app detail 頁。
Container 按鈕 → GET …/api/v1/code_changes
回傳 { [containerName]: { "url": string } }；以 container name 查 map，缺 key 顯示 Not Found。

所有 HTTP 必須走 @grafana/runtime 的 getBackendSrv()（Grafana proxy），panel 不直連外部 URL。 換選節點時 hook 重置為 idle 並 abort in-flight 請求。

8. React 新手速成：用 TypeScript 角度看這個 repo

你如果懂 TypeScript，可以把 React component 想成「接收 props、回傳 JSX 的函式」。

Component = typed function

export function KsgPanel(props: Readonly<KsgPanelProps>): React.JSX.Element {
  const { options, data } = props;
  return <div>...</div>;
}

Readonly<...> 表示 component 不應該 mutate props。React 的資料流是父層傳 props 給子層， 子層用 props 渲染 UI。

JSX 是什麼？

JSX 是 JavaScript XML 的縮寫。它讓你在 JavaScript / TypeScript 裡寫「像 HTML 的語法」， 但它不是瀏覽器原生 HTML，也不是字串。JSX 是一種語法糖，編譯後會變成 JavaScript function call。 

const title = 'KSG Demo';

export function Header(): React.JSX.Element {
  return <h1>{title}</h1>;
}

上面這段 JSX 編譯後，概念上會接近下面這種 JavaScript：

import { jsx } from 'react/jsx-runtime';

const title = 'KSG Demo';

export function Header() {
  return jsx('h1', { children: title });
}

React 拿到這個 function call 產生的 React element 物件後，會知道「畫面應該有一個 h1，children 是 title 的值」。之後 React 會比較新的 element tree 與目前畫面，決定實際 DOM 要更新哪些部分。

JSX 跟 HTML 差在哪？

觀念 HTML JSX
本質 瀏覽器解析的 markup。 編譯成 JavaScript function call 的語法。
class 屬性 <div class="box"> <div className="box">
label for <label for="name"> <label htmlFor="name">
事件 onclick="..." onClick={handleClick}
插入變數 通常靠 template engine 或手動組字串。 用 {expression} 插入 JavaScript 表達式。

JSX 的大括號是 JavaScript 表達式

JSX 裡的 {...} 可以放 JavaScript 表達式，例如變數、三元運算、函式呼叫、陣列 map。但不能直接放 statement，例如 if 或 for。 

const isLoading = data.state === LoadingState.Loading;

return (
  <div>
    {isLoading ? <LoadingOverlay /> : <GraphCanvas elements={elements} />}
  </div>
);

如果邏輯變複雜，通常先在 JSX 外面算好變數，再把結果放進 JSX，這樣比較容易讀。

Component tag 其實是 function call

小寫 tag 例如 <div>、<h1> 代表瀏覽器 DOM element； 大寫 tag 例如 <GraphCanvas>、<HoverTooltip> 代表 React component。 

<GraphCanvas
  elements={elements}
  stylesheet={stylesheet}
  layout={options.layout}
/>

這可以理解成：「呼叫 GraphCanvas 這個 function，並把 elements、stylesheet、layout 當 props 傳進去」。 TypeScript 會檢查這些 props 是否符合 GraphCanvasProps。

Hook = 可重用的狀態或副作用邏輯

本 repo 大量使用 hooks，是因為 Grafana panel 與 cytoscape 都需要跟外部系統同步。

Hook 你可以怎麼理解 本 repo 例子
useMemo 用輸入計算輸出，輸入沒變就重用結果。 useGraphData 只在 data.series 變動時重新 normalize。
useEffect 處理外部副作用，例如建立 cytoscape instance、註冊 event、改 DOM-like graph 狀態。 useCytoscape 的 init / cleanup。
useRef 保存 mutable reference，不觸發 React re-render。 cyRef 保存 cytoscape instance。

為什麼 cytoscape 不放 React state？

因為 cytoscape instance 很大，而且它自己有一套 imperative 狀態，例如 nodes、edges、layout、listeners。 如果把它放 React state，會讓 React 重複 render，還容易造成 StrictMode double-mount 下 listener 殘留。

本 repo 的模式：useRef 保存 cy， useEffect 在 props 變動時 imperative 更新 cy。

在這個 repo 裡怎麼讀 JSX

讀 KsgPanel.tsx 時，可以先忽略細節，把 JSX 看成條件式 UI 描述： loading 時顯示 LoadingOverlay，資料錯誤時顯示 Alert， 有資料時顯示 GraphCanvas + 左側 legend rail，選取節點時顯示 NodeDetailPanel（左鍵 alerts / 右鍵 detail）。

何時新增 component？

  • 一段 UI 有清楚職責，例如 NodeLegend、EdgeLegend、HoverTooltip。
  • 它可以用 props 描述輸入。
  • 它的測試可以獨立寫。
  • 不要為了「看起來比較 React」拆太碎；先依 feature 邊界拆。

12. Best Practices

專案邊界

  • Feature-first，不是 type-first。每個 feature 自己有 components、hooks、純函式與測試。
  • 跨 feature import 走 barrel。例如從 features/graph-canvas 對外 export，不要亂鑽內部檔案。
  • shared 只放真正跨 feature 的東西。不要把所有工具都塞進 shared。
  • 新增功能先問邊界。如果新程式只服務某個功能，先放該 feature；等第二個 feature 真的需要再抽到 shared。
  • feature 內部可以自由整理，外部 API 要穩。外部使用者依賴的是 index.ts export，不是內部資料夾形狀。

TypeScript

  • 避免 any；cytoscape 事件用 cytoscape.EventObject 等原生型別。
  • 因為啟用 noUncheckedIndexedAccess，陣列或 object index 取值都要處理 undefined。
  • 因為啟用 exactOptionalPropertyTypes，optional field 要小心，不要把 undefined 當成任意值塞。
  • 自訂 cytoscape node / edge data 欄位集中在 src/shared/types/cytoscape.d.ts。

React

  • Function components only；src/** 禁止 default export。
  • derived data 用 useMemo，不要用 useEffect + useState 硬同步。
  • useEffect 只用於真的外部副作用，例如 cytoscape、DOM observer、event listener。
  • Component props 用明確型別，避免把一大包不透明 object 往下傳。

cytoscape

  • cytoscape instance 是 graph 的唯一真實狀態源。
  • instance 放 useRef，不要放 React state。
  • init effect 與 update effects 要拆開。
  • cleanup 必須 removeAllListeners()、destroy()、cyRef.current = null。
  • elements 更新走 diff-and-patch，不要每次 remove all + add all。
  • 大量更新包在 cy.batch() 裡。
  • extension registration 只在 module top-level 做一次，也就是 registerExtensions.ts。

資料契約

  • normalizeGraph 是 anti-corruption boundary。外部 payload 的容忍與轉換都應集中在這裡。
  • rendering layer 不應該到處知道上游欄位名稱，例如 type 或 ipaddress。
  • unknown kind 預設可見，避免上游新增類型時被靜默藏掉。
  • edge 如果 source / target 不存在，normalize 應回 error 並略過該 edge。

樣式與常數

  • iconSvgByKind.ts 與 colorByEdgeType.ts 是 node / edge 視覺的單一資料源。
  • Legend、filter option、stylesheet 都應從常數 map 派生。
  • 不要在三個地方分別手寫同一份 kind / edge type 清單。
  • cytoscape stylesheet 用 pure factory，方便單測。
  • panel 對外 HTTP 必須走 getBackendSrv() + Grafana datasource proxy，不要自建 fetch client 直連外部。

Node Detail

  • 左鍵 / 右鍵 view 分流保持互斥：alerts 與 Application/Containers 不要在同一 view 混排。
  • Change Report 維持 lazy：右鍵開面板不 eager fetch；成功用 window.open，不在 panel 內嵌 URL。
  • 表格元件 presentational，查詢狀態集中在 useNodeDetailUrls。

測試策略

  • 純函式直接 Jest：normalizeGraph、diffElements、computeVisibility、getStylesheet。
  • Hook 測 cytoscape 時用 headless mode。
  • Component 用 Testing Library，測使用者看得到的狀態。
  • 修改 shared 行為時，測試範圍要放大，因為 blast radius 大。

14. 常見問題

KSG Demo 顯示 datasource 錯誤，但 Showcase 正常

預期行為：未加 --profile backend 時 backend stack 未啟動，KSG Demo 的 Infinity proxy 會失敗。 執行 docker compose --profile backend up -d 或改用 KSG Showcase。

Change Report 按鈕永遠 disabled 或查詢 404

  • 確認 backend 已實作 /api/v1/config_changes 與 /api/v1/code_changes。
  • 檢查 detailEndpoint option 或 datasource proxy 推導是否正確（DevTools Network）。
  • 節點需有 application 欄位且為右鍵觸發（左鍵不發查詢）。
  • backend 未就緒時 lazy 模式不會在開面板時顯示 Not Found——需點擊按鈕才會看到錯誤。

pod_list 變數沒有更新

  • 確認 panel option podListVariable 與 dashboard 變數名稱一致。
  • 變數必須事先存在於 dashboard templating（panel 不能建立變數）。
  • query 失敗或 normalize 整包失敗時 intentionally 不寫入。

Grafana 顯示 unsigned plugin warning

開發模式需要允許未簽署 plugin。compose base 通常會設定 GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS=marz32one-ksg-panel。

Datasource ksg-default 找不到

  • 確認 Infinity datasource plugin 是否安裝：GF_INSTALL_PLUGINS=yesoreyeram-infinity-datasource。
  • 確認 provisioning datasource YAML 存在並被 Grafana 掛載。
  • 確認 dashboard 的 datasource UID 與 provisioning UID 都是 ksg-default。

Port 3000 或 8080 被佔用

停掉其他服務，或改 compose port mapping。Grafana 預設是 3000，backend 預設映射 8080。

Backend 沒有資料 / 連不到 metrics store

  • 確認 victoriametrics 與 ksg-seeder 都在跑：docker compose ps。
  • 確認 backend 的 KSG_PROM_URL 指到 http://victoriametrics:8428。
  • 直接查 VictoriaMetrics 看 seeder 有沒有灌進去： curl 'http://localhost:8428/api/v1/query?query=up' 或查 topology metric。
  • 看 docker compose logs kube-state-graph 與 docker compose logs ksg-seeder。

Panel 顯示 No graph data

  • Backend 可能回 empty payload。
  • Datasource query 可能沒有打到 /v1/graph。
  • useGraphData 可能沒有在 Grafana frames 中挑到 graph payload。

Panel 顯示 Graph data malformed

  • payload 不是 object。
  • nodes 或 edges 不是 array。
  • node 缺 id 或 type。
  • edge 缺 id、source、target、type。
  • edge 參照了不存在的 node id。

改了程式但畫面沒變

  1. 確認 npm run dev 還在跑。
  2. 確認 webpack 有 rebuild。
  3. 重新整理 Grafana 頁面。
  4. 必要時重啟 Grafana container。

15. 名詞表

名詞 意思
Grafana panel plugin Grafana dashboard 裡的一種視覺化元件。本 repo 產出的 plugin 會被 Grafana 載入。
Infinity datasource Grafana 社群 datasource plugin，可把 HTTP JSON 等外部資料轉成 Grafana query response。
PanelData Grafana 傳給 panel 的資料物件，包含 series、loading state、errors。
cytoscape.ElementDefinition cytoscape 的 node / edge 描述格式，通常長得像 { group, data }。
normalize 把外部不穩定資料轉成內部穩定資料的 boundary；normalizeGraph 把上游 cytoscape JSON 映射成 ElementDefinition[]。
deserialization 本 repo 指 extractJsonFromFrames（從 Grafana frame 抽出 JSON）+ normalizeGraph（驗證與欄位映射）兩步。
Stylesheet cytoscape 的 selector → style 規則陣列；由 getStylesheet(theme) 產生，決定 node shape、edge 顏色、compound 容器外觀等。
fcose cytoscape 的 force-directed layout extension。
dagre cytoscape 的階層式 layout extension。
PodParentMode 'node' | 'controller'：決定 pod 嵌在 K8s node 還是 workload controller 下，以及哪些 edge 被繪製。
Change Report Node Detail 中 lazy 觸發的 REST lookup，經 Grafana proxy 查 config/code changes 並開新分頁報告。
getBackendSrv @grafana/runtime 提供的 HTTP 客戶端；panel 對外 REST 必須走它（含 Change Report），不可直連外部 URL。
barrel index.ts re-export 對外 API，讓其他 feature 不需要 import 內部路徑。
